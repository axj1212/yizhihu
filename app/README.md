# 医智呼 · AI 随访外呼系统（融合版）

以医生视角编排病种与分阶段随访计划，AI 自动电话外呼患者，语音转写后由大模型解析为结构化数据回存系统，并按四级风险自动生成分级工单——覆盖「编排 → 外呼 → 解析 → 预警 → 处置」的完整闭环。

## 快速启动

```bash
pip install -r requirements.txt
python run.py            # 默认 http://127.0.0.1:8000
```

首次启动自动初始化演示数据：5 个病种随访方案、25 名脱敏糖尿病患者（医智呼患者名单）、40 名 HIS 出院患者、41 份随访计划与历史通话。

线上演示：见参赛材料中的认证链接。大模型调用读取项目根目录 `APIkey.txt`（或环境变量 `AGNES_API_KEY`）；模型不可用时自动降级为规则引擎，全流程不中断。

## 功能地图

| 模块 | 说明 |
|---|---|
| 工作台 | 在访患者、今日待呼、完成率、风险分布、7 日外呼趋势、待办工单 |
| 病种随访方案 | 医生编排阶段（D3/D7/D14/D30/D90）、提问、追问分支与红旗；AI 一键重写话术，医生审核后发布 |
| 患者档案 | 名单检索、Excel 导入、建档即自动匹配病种生成计划；再入院登记不改写已固化计划 |
| 外呼中心 | 任务队列、单呼/批量外呼、通话转写回放、结构化字段、风险等级、关联工单 |
| 风险工单 | 蓝/黄/橙/红四级，SLA 时限（红 12h、橙 24h、黄 24h），处置闭环 |
| 云服务接入 | 医生邮箱验证码登录、随访结果云数据库同步、随访资料云存储、免密钥大模型话术生成、一键接入自检 |
| 系统设置 | 阿里云线路配置、白名单、演练/真实模式切换、业务日期、模型状态 |

## 关键机制

- **分阶段话术**：按出院 3/7/14/30/90 天生成节点；高危并发症患者自动加密（3 天首访、14 天复访）。
- **计划固化**：计划创建即快照（诊断、出院日期、问题清单），患者再入院或有新医嘱只追加事件，不改写原计划。
- **脱访识别**：患者表示转院 → 自动终止计划；连续 5 次未接通 → 判定失联转人工；未接通按 30 分钟/次日重拨。
- **结构化解析**：通话文本 → 用药依从性、空腹/餐后血糖、症状、不良反应、复诊落实等字段；大模型抽取 + 规则引擎兜底。
- **风险分级**：规则引擎最终裁决（血糖≥16.7 或意识改变等 → 红色；空腹>9、自行停药、足部破溃等 → 橙色），避免模型幻觉漏报。
- **真实外呼**：`app/providers/aliyun.py` 实现阿里云 dyvmsapi V3 签名（SingleCallByTts），配置 AccessKey 并切换真实模式后，仅拨打白名单号码；回执经 `/api/calls/aliyun-callback` 回写录音与转写。

## 云服务接入（已开通）

应用已绑定 WorkBuddy 云服务的**单一环境**（一个应用一个环境，四个模块共用）。公开配置集中在 `app/static/cloud-config.js`，由激活时返回的 `publicConfig` 生成；`endpoint`、`publishableKey`、`oauthRelayBaseUrl` 只在 `cloud.js` 中初始化一次，所有模块复用同一个 `cloud` 实例。

| 模块 | 落点 | 说明 |
|---|---|---|
| Auth | 医生账号 · 云端身份 | 邮箱 OTP 登录/注册，无密码；会话自动附加到数据库、存储与模型请求 |
| Database | `followup_records` / `doctor_notes` | 前者为科室共享的 AI 外呼结构化结果与风险分级（公共读、可写，已开启 RLS）；后者为医生私有处置备注（`owner_id TEXT DEFAULT auth.uid()`，按行级隔离） |
| Storage | `shared/<uid>/reports/` | 随访报告/名单文件上传、列表、10 分钟签名下载链接；限制 txt/md/json/csv/xlsx/pdf 且 ≤5 MB，登录后可用 |
| LLM | 免密钥模型调用 | `models.list()` 选择模型，`chat.completions.create({stream:true})` 生成分阶段随访提问，解析后可写回病种方案并标记「待医生审核」 |

**端到端自检**：`https://<应用域名>/static/selftest.html?stage=test`（另支持 `stage=sync` 同步真实外呼结果、`stage=ai` 生成话术、`stage=send` / `stage=verify` 完成邮箱验证码登录）。页面结果也会写入 `followup_records` 便于从云端核对。

已验证：会话状态、34 个可用模型目录、免密钥模型返回、云数据库写入读回一致、条件查询与分页、跨用户改写被 RLS 过滤影响 0 行、私有备注读回、未登录时的存储门禁、失败路径文案、自检报告入库；12 条真实 AI 随访结果（含结构化 JSON）已同步；云 AI 一次生成 5 个带追问分支的随访提问。

**需要人工完成一次的操作**：邮箱验证码需由本人收取，因此「登录产生身份」与「登录后上传文件并打开签名链接」要在浏览器里点一次——进入「云服务接入」页输入邮箱 → 获取验证码 → 登录/注册，随后即可上传资料并点击「打开」。未登录时这些操作会被明确拦截，不会静默降级。

> 注意：云服务的 `endpoint` 与发布域名严格绑定，重新发布必须复用同一个 `applicationId`，否则登录会因 Origin 不匹配而失败。
